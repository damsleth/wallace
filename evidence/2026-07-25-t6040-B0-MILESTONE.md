# 🐧 MILESTONE B0 — untethered Linux boots on the M4 Pro (2026-07-25)

**A cold boot from the Apple boot picker, with no cable and no host involvement,
reaches an interactive Alpine/OpenRC shell on the internal display of a J614s
MacBook Pro (M4 Pro, T6040).** Ticket 101 passes; the mission goal set at the start
of the project — "an untethered Linux distro on the M4, booting by itself" — is met.

## What made it work

1. **16 KiB page alignment of the enrolled object** — the root cause of every previous
   failure, found after six wrong theories
   (`evidence/2026-07-25-t6040-enrolled-payload-rootcause.md`). The builder now enforces it.
2. **The diet kernel** — `DIET=1` in `t6040-kbuild.sh` cut the Image from 50.8 to
   16.8 MiB (−67%) by dropping ~40 non-Apple ARM64 platforms and every subsystem with
   no B0 consumer, with a 31-symbol assertion that the boot essentials survived.
3. **XZ payload members** — minilzlib-compatible (`-9e --check=crc32 -T1`), cutting the
   object from 22.2 MB to 9.02 MiB before padding.
4. **The Norwegian keymap fix** — BusyBox has no `loadkeys`; it provides `loadkmap`,
   which takes a *binary* keymap on **stdin** and has no applet symlink, so the service
   must call `busybox loadkmap < …/no-mac.bmap`.
5. **HID `hid->type`** (ticket 078, earlier) — without it the rebased `hid-apple`
   rejects the internal keyboard and there is no `event0`.

## Honest note on the path here

The mechanism hunt took six wrong hypotheses (object size in MiB, compression format,
kernel size, m1n1 prefix, SEPFW adjacency/load extent, the early-proxy window, and
payload content/obfuscation). The recurring error was inferring from absence — missing
console output, a missing USB gadget node, stale RAM misread as a live result — and,
decisively, **building controls that silently differed from the test cases in an
untracked variable**: every filler probe was accidentally page-aligned. What finally
worked was tabulating all ten objects against one measurable property.

## Cosmetic follow-up seen in the boot

`sysctl` prints ~13 `unknown key` errors for `net/ipv4/*`, `net/ipv6/*` and
`kernel.unprivileged_bpf_disabled` — expected, because the diet kernel has `CONFIG_NET`
and BPF disabled while Alpine's stock `sysctl.conf` still references them. Harmless; a
small ticket trims the sysctl service or its config for a clean boot.
