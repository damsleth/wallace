## How the diet works — `DIET=1` in `scripts/t6040-kbuild.sh`

`arm64 defconfig` is the bloat source: it enables ~40 non-Apple ARM64 platforms
plus every major subsystem. `DIET=1` runs after the normal variant config and:

- disables every `CONFIG_ARCH_*` **platform** except `ARCH_APPLE` (skipping the
  generic `ARCH_HAS_*`/`ARCH_WANT_*`-style capability flags, which are not
  platforms);
- drops subsystems with no B0 consumer: `NET` (the B0 root has zero network
  services), wireless/BT, sound, media, `PCI`, `USB_SUPPORT`, SCSI/NVMe/ATA/
  MMC/MTD, **all disk filesystems** (a cpio RAM-root needs none), KVM/virt,
  ftrace/kprobes/BPF/`KALLSYMS_ALL`, debug info, and `MODULES` entirely;
- re-asserts the RAM-root essentials, then **verifies 31 boot-essential symbols
  are still `=y` after `olddefconfig` and aborts the build if any was dropped as
  a dependency side effect** (plus re-checks `ARM64_SME` stayed off).

Verified on the produced `config-b0-diet`: all 31 essentials present, SME off,
and NET/SOUND/PCI/USB/SCSI/EXT4/MODULES/FTRACE/BPF/KVM all confirmed dropped.

## Incident: the proven kernel was overwritten and restored

The script names outputs from the variant flags, so `DIET=1` wrote its Image to
`/out/Image-hid-type-fix`, clobbering the 50.8 MiB ticket-100 kernel. Recovered
byte-exact by decompressing the untouched `Image-hid-type-fix.gz` — restored
file hashes `df7657c1…`, the proven value. Diet artifacts renamed to
`Image-b0-diet` / `System.map-b0-diet` / `config-b0-diet`. **Follow-up:** give
`DIET=1` its own output name in the script so this cannot recur.

## Next levers if 9.01 MiB is still over the wall
