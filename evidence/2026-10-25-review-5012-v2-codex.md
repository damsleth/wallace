# Codex review of 5012 probe v2 (claude via agent-bridge, codex medium = gpt-6.1-sol), 2026-10-25

Applied: validated 3-level walk (p4d/pud fold), Device-alias read removed, software-root PA logged beside TTBRs, IPI failures logged, civac pinned with get_cpu, control (broadcast TLBI then AT) before the test (civac, dsb sy, broadcast TLBI, AT).

- **(a) Crash risk: unchecked page-table descent.** `t6040_205_probe_v2()` calculates every lower-level pointer without checking present/table/leaf descriptors. An absent mapping or PMD block makes `ptep` bogus; `virt_to_page()`, the descriptor reads, or cache maintenance can then fault or target unrelated memory. Validate each real level before descending, even if previous evidence establishes an L3 mapping.

- **(a) API and context otherwise look valid for the supplied configuration.** The local tree has the two-address `dcache_clean_inval_poc()` signature and all referenced sysreg definitions. `vmap(&tpg, 1, VM_MAP, prot)` accepts this page array; `PAGE_KERNEL_RO` is compatible with the read. Allocation and unmapping occur in initcall process context, while the IPI callback only reads registers/memory and does not sleep. The synchronous callbacks finish before init memory is freed; there is no `__init` lifetime problem. Arm64 selects `ARCH_KEEP_MEMBLOCK`, so `memblock_is_map_memory()` remains available.

- **(a) No inherent VHE register-access UNDEF under your stated assumptions.** The EL1 accessor names redirect to the host EL2 registers, including the feature-gated TCR2/PIR/PIRE0 accesses. Feature presence alone does not override applicable EL3 access restrictions, but E2H itself does not make these accesses illegal. The callback has no EL1 fallback: running this image outside the assumed EL2 environment would fault on its unconditional EL2 reads. [Arm register access rules](https://support.arm.com/documentation/ddi0601/2026-09/AArch64-Registers/PIRE0-EL2--Permission-Indirection-Register-0--EL2-?lang=en)

- **(b) The “uncached DRAM contents” claim is invalid.** Here `pgprot_noncached()` produces **Device-nGnRnE**, not Normal noncacheable memory. This creates a conflicting memory-type alias of an actively cacheable page-table page. `vmap()` does not establish a coherent cache-to-DRAM snapshot or clean that page’s dirty cache lines. The aligned read need not immediately crash, but its result cannot reliably establish DRAM contents. Using Normal-NC instead would still require resolving the cacheability-alias/coherency problem.

- **(b) These are per-CPU loads of one software walk, not per-CPU walks.** All callbacks dereference pointers computed once from `pgd_offset_k()`. If a secondary’s TTBR actually selects another root, the logged descriptors still come from `init_mm`’s root. Compare each TTBR’s decoded root address with the software root before interpreting matching descriptor values as matching walker inputs.

- **(b) Folded entries are duplicates.** With 16K pages and 47-bit VA, the three hardware levels are L1/L2/L3; Linux’s p4d and pud are folded. The pgd/p4d/pud records therefore identify the same underlying entry, not three independent hardware descriptors. Their repeated maintenance is harmless but redundant.

- **(b) CIVAC is a useful intervention, with narrower conclusions.** Cleaning the actual dirty producer’s descriptor lines to PoC, followed by `dsb(sy)`, should publish those lines for a coherent walker; the supplied API performs line-based maintenance. However, it neither invalidates TLB/walk-cache state nor forces subsequent AT instructions to fetch descriptors anew. Consequently, unchanged PAR values do **not** exclude the stale-memory hypothesis. A changed result also needs isolation from earlier alias creation, allocation, logging, and timing effects.

- **(b) “cpu0” is not guaranteed.** The initcall’s mapping, alias read, and CIVAC loop are not explicitly CPU-bound. An init thread can migrate; identify/pin the executing CPU before claiming that CPU0’s dirty cache was specifically tested. Also, log `smp_call_function_single()` failures rather than letting an untouched zero record resemble a successful read.

- **(c) Verdict:** Useful register comparison, but validate the walk, remove the conflicting alias, and tighten CPU/TLB controls before treating v2 as evidence about walker-visible memory.
