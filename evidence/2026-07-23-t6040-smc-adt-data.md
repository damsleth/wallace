## `/arm-io/smc` (compatible `iop,ascwrap-v6`, interrupt-parent = AIC)

DT reg mapping is the proven ADT→DT split (`0xABCDEFGHI` → `<0xA 0xBCDEFGHI>`,
same as dockchannel `0x50880c000`→`<0x5 0x0880c000>`):

| ADT reg | DT `reg` cell | size | likely role |
|---|---|---|---|
| `0x30c600000` | `<0x3 0x0c600000 …>` | `0x88000` | ASC wrapper (mailbox + SMC core region) |
| `0x30c050000` | `<0x3 0x0c050000 …>` | `0x4000` | secondary control window |
| `0x30c810000` | `<0x3 0x0c810000 …>` | `0x100` | small control/SRAM-index window |

ASC mailbox IRQs (AIC inputs, the four ASC doorbells in order): **997, 996,
999, 998** (send-empty, send-not-empty, recv-empty, recv-not-empty). Single
child node `iop-smc-nub`.

## DT authored (2026-07-23) — `dts/t6040-j614s-dcuart-smc.dts`

Resolved the layout: `iop-smc-nub` gives `region-base 0x50df00000`/`0x100000`
(the RTKit shared SRAM, a RAM carveout — not an MMIO aperture as on t8112) and
children `smc-pmu` (event bits pwrbtn=0, lid=8, sdconn=9, charger=11) +
`smc-charger-util*` (charger control). The upstream Asahi ASC reg convention
(t8112) is **block@base+0x0 (smc, 0x4000)** + **mbox@base+0x8000 (0x4000)**, so
the T6040 ascwrap `0x30c600000` maps to smc@`0x30c600000` + mbox@`0x30c608000`.

Authored a **read-status-only** macsmc node on the dcuart console base:

- `smc@30c600000` `apple,t6040-smc`,`apple,smc`; reg = `<0x3 0x0c600000 .. 0x4000>`
  (smc) + `<0x5 0x0df00000 .. 0x100000>` (sram = the nub carveout);
  `mboxes = <&smc_mbox>`.
- `smc_mbox@30c608000` `apple,asc-mailbox-v4`; IRQs **997/996/999/998**
  (send-empty/send-not-empty/recv-empty/recv-not-empty, ADT order).
- children: `smc_gpio` (gpio-controller, no line driven here) + `smc_hwmon`
  (battery gauge + thermals).
- **Deliberately omitted `smc_reboot` + `smc_rtc`** — those write PMIC NVRAM
  (boot_stage/shutdown_flag/rtc_offset) through the PMU/SPMI path, which
  remains absolutely prohibited; `smc-charger-util` is never wired. The
  right-HPM2 exception in `docs/SPMI_SAFETY.md` does not apply.

Built + verified (kernel dtc): 6 smc/mailbox/gpio/hwmon nodes present, **0**
reboot/rtc nodes. **DTB SHA-256
`aced33f7477b07f2e621ab0cc342f74bd07959f2f07ffe93a383903bc288a2e2`**, dtc-clean.
No 26.x SMC compat patch needed (ticket 028).

## Three items to confirm before a rig boot (flagged, not blocking authoring)

1. **sram = a RAM carveout** (`0x50df00000`), not an MMIO aperture — confirm the
   `apple,smc` driver binds against a carveout-backed sram (and that m1n1
   reserves it), or adjust once an M4-era macsmc reference exists upstream.
2. **mailbox sub-offset** (`ascwrap+0x8000`) is the t8112 convention inferred
   onto T6040's single ascwrap reg; ADT gives the whole `0x88000` block, not the
   split. Verify against a working probe.
3. **power-button/lid** arrive via `smc-pmu`; confirm the macsmc path is
   SMC-mediated (RTKit notifications), not a direct PMU write, before relying on
   it. Battery/thermal (this node) needs none of the three.
