# Codex review of 5012 probe v3 (claude via agent-bridge, codex medium), 2026-10-25

Verdict: sound for T6040. Not changed: ADT 592 KiB < 1 MiB slack; adt_end is 16 KiB aligned (m1n1 ALIGN_UP); CPU ids < 64. Interpretation: the map is of AT write-translation failures (PAR.F), not specifically permission denials; uniform all-CPU failures (mask 0x3f) are distinguishable from the secondary-only pattern.

- **(a) Bounds and compilation:** The bitmap declaration is valid: `DECLARE_BITMAP(map[NR_CPUS], 4160)` produces one 4160-bit bitmap per CPU. `map_n` is capped at 4160, so neither bitmap nor skip-array indexing overruns. Static storage costs `520 * NR_CPUS + 4160` bytes; large configurations waste memory, but this is no stack overflow. ([lines 241–269](patches/t6040-205-fault-tlbi-retry-diag.patch:241))

- **(a) Run printing is correct for `n > 0`:** Runs have exclusive end addresses, transitions include the preceding page, and `i == n` flushes the final run without indexing page `n`. Short-circuit evaluation prevents reading `mask` in the condition at that sentinel. The subsequent `prev = mask` reads the last iteration’s initialized value and is harmless. For hypothetical `n == 0`, that assignment reads an uninitialized variable; the stated ADT window guarantees nonzero `n`. ([lines 282–300](patches/t6040-205-fault-tlbi-retry-diag.patch:282))

- **(a) `__va` does not dereference the PA:** The validity/map-memory checks exclude ordinary holes and NOMAP regions before translation. Under the stated arm64 configuration, converting eligible RAM to its linear-map VA is appropriate. A missing linear-map PTE yields an AT failure rather than a load/store fault. These checks do **not** establish that the mapping exists or permits writes. ([lines 252–257](patches/t6040-205-fault-tlbi-retry-diag.patch:252), [273–274](patches/t6040-205-fault-tlbi-retry-diag.patch:273))

- **(a) Long IRQ-off callbacks:** Each synchronous callback performs roughly 4100 serialized AT/ISB/PAR sequences with local IRQs disabled, including the self-call path. This delays interrupts and perturbs timing; it is not inherently a deadlock or proof of watchdog failure. Actual duration needs measurement; smaller batches would bound latency. ([lines 252–258](patches/t6040-205-fault-tlbi-retry-diag.patch:252), [276–277](patches/t6040-205-fault-tlbi-retry-diag.patch:276))

- **(b) The advertised window can be incomplete:** Capacity covers 64 MiB plus only 1 MiB of ADT span. A larger ADT silently truncates the upper window. Independently, integer division rounds the upper endpoint **down**, omitting the final intersecting page when `adt_end` is unaligned; use an aligned-up exclusive endpoint for page coverage. ([lines 267–269](patches/t6040-205-fault-tlbi-retry-diag.patch:267))

- **(b) “Deny” overstates the observation:** `PAR.F` includes translation faults and other failures, not just write-permission denial. Legitimately read-only mappings also set it. This map identifies failed write translations; it cannot alone identify the anomalous permission fault or prove actual stores succeed when the bit is clear. ([lines 255–257](patches/t6040-205-fault-tlbi-retry-diag.patch:255))

- **(b) CPU-mask limitations:** CPU IDs ≥64 make `BIT_ULL(cpu)` invalid, and all 64 CPUs failing collides with the `~0ULL` skip sentinel. Neither affects a T6040 with logical IDs below 64. CPU scans are sequential, so the masks also combine observations from different times. ([lines 284–297](patches/t6040-205-fault-tlbi-retry-diag.patch:284))

- **(c) Verdict:** Bounds and final-run handling are sound for the stated target; fix or explicitly disclose window truncation/rounding and label the result as an AT-failure map before treating it as exact.
