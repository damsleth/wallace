# 5010 per-CPU sysreg diff (claude, 2026-10-25): boot-core baseline captured; secondary reads blocked by a tooling defect

Lease `claude`, m1n1 `7de07c71` chainloaded over the rollback. Reviews: Mythos
PASS-with-must-fixes (`evidence/2026-10-25-review-5010-cpu-sysreg-diff.md`)
plus the run-2 plan. Reads only (`mrs` under the m1n1 exception guard).

## Run 1: wedged with no attribution

A blind sweep of every `s3_{0-7}_c15_c{0-15}_{0-7}` encoding. m1n1 started
all secondaries (CPU index 0 to 14). Then there was no output: stdout was
block-buffered through `tee`. The proxy was dead at the 20 min timeout, and
the machine was recovered by reboot. Which read hung is unknown. The script
was narrowed to the registers m1n1 names in `cpu_regs.h`.

## Run 2: cpu0 complete; secondaries cannot execute the proxy code buffer

First pass (Mythos list): 21 architectural ID/MMU registers plus 42 named
configuration registers on cpu0, cpu1 and cpu5. JSON was written after every
read, and the progress file before every read.

- **cpu0 (boot P, MPIDR 0x80010100, MIDR 0x611f0551): all 63 read**, 51
  defined and 12 UNDEF (`run2-sysregs.json`). Key values: `ACTLR_EL2=0xc00`,
  `HCR_EL2=0x32488000038`, `HID4=0x30800000000`, `HID5=0x0082cf605741ef11`,
  `HID6=0x006598432ca18818`, `HID7=0x1665a00008001000`,
  `HID11=0x4000000000201`, `HID18=0x40028006020`, `SPRR_CONFIG_EL1=0`,
  `APCTL_EL2=0xc`, `ACC_CFG=0xd`, `CYC_OVRD=0`.
- **cpu1 (E, MPIDR 0x1): its first three reads returned None, and the fourth
  rebooted m1n1.** The m1n1 console shows
  `ESR 0x86000000 (instruction abort (current))`, then
  `Unhandled exception, rebooting...`. The secondary took an instruction
  abort at the proxy code buffer, which `ProxyUtils.exec` calls through the
  `REGION_RX_EL1` alias: executable on cpu0, evidently not on the secondaries
  in this m1n1. The exception guard skipped the first three aborts; the
  fourth was unhandled. **This is a tooling defect. It says nothing about the
  CPU or about 205.**

Per the agreed rule (stop after two wedges in one lease), run 3 was not
attempted.

## Fix for run 3 (offline, next lease)

Call secondaries at the code buffer's physical address (region 0: pass
`call=(secondary_call(cpu), 0)` to `u.mrs`) rather than the RX_EL1 alias, or
verify m1n1's secondary MMU mapping first with a single NOP call. Keep the
async spin_table poll, the per-read progress, the JSON after every read, and
the stop-after-two-wedges rule. cpu0's baseline is already on disk; run 3
needs cpu1, cpu5 and cpu6.

## Run 3 (2026-10-25 13:4x): complete, no hang. **P secondary = boot P in every named configuration register except SIQ_CFG_EL1**

Fix applied (Mythos e46bbd4 explanation): `smp_start_secondaries` leaves
secondaries **MMU-off**, the same state Linux receives them in, so their calls
use the code buffer's physical address after `dc cvac`. A NOP sanity call
passed on cpu1 and cpu5. All 63 first-pass registers were read on cpu0, cpu1
(E, MPIDR 0x1) and cpu5 (P, MPIDR 0x10101, the 205 threshold core).
Files: `run3-sysregs.json`, `run3-diff.txt`.

cpu5 against cpu0:
- **Identical:** HID0, HID1, HID3–HID14, HID16, HID18, HID21, HID26, HID27,
  ACTLR_EL2 (0xc00), HCR_EL2, APCTL_EL1/EL2/EL12, ACC_CFG, ACC_OVRD, CYC_OVRD,
  SPRR_CONFIG_EL1, GXF_CONFIG_EL1, IPI_CR_EL1, AMX_CTL, all ID registers and
  the _EL12 MMU registers.
- **SCTLR_EL2/TCR_EL2/MAIR_EL2:** expected, since cpu0 runs m1n1's MMU and the
  secondaries are MMU-off. Linux rewrites these per core.
- **EHID\* and SPR_LOCKDOWN_EL1/EL2** read `0` on cpu5 and UNDEF on cpu0. This
  is a measurement artefact: a guarded UNDEF on a secondary returns the stale
  return value 0, because the secondary path does not surface exc_count. They
  are not real values.
- **`SIQ_CFG_EL1` (System Interrupt Configuration): cpu0 = 0, cpu1 = 3,
  cpu5 = 3.** This is the only configuration difference. m1n1 writes 2 on
  older parts whose feature flag asks for it ("0 causes pathological behavior
  in EL1, 2 works"), but leaves T6040 untouched. iBoot left the boot core at 0.

## Reading

- "The P secondaries lack the boot core's chicken bits" is **refuted for the
  named HID/ACTLR/APCTL/ACC/CYC/SPRR set**: iBoot's values are already present
  on cpu5.
- **SIQ_CFG_EL1 is the lead.** Correction (Mythos, 2026-10-25): 205 is not
  P-secondary-specific. Ticket 208's BusyBox reproducer faulted 2 of 4 runs
  at `maxcpus=2` (cpu0 plus the E core cpu1); the maxcpus=5 "works" result
  only meant the boot reached userspace, not that it was fault-free. The
  asymmetry to look for is the boot core against every secondary, and
  SIQ_CFG_EL1 (cpu0 0, every secondary 3) is the only named register with
  that shape. m1n1 writes SIQ_CFG_EL1 = 2 on every core for M1, M2 and M3
  (`chickens.c`, `.siq_cfg` in features_m1/m2/m3), but `features_m4` (an
  "XXX" placeholder, the same upstream) omits it. M4 is the only generation
  m1n1 leaves heterogeneous. Next: ticket 5011 (`.siq_cfg = true` for M4,
  so every core reads 2), with the 208 reproducer at maxcpus=2 and 6 against
  a same-day control.
- Not covered yet (second pass): the GL/GL12 block, PMC/UPMC, error-status
  registers, and the unnamed c15 encodings (run 1 wedged in that sweep).
  E-core-only registers on cpu1 need an E-core reference rather than cpu0.
