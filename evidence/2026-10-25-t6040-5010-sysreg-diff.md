# 5010 per-CPU sysreg diff (claude, 2026-10-25): boot-core baseline captured; secondary reads blocked by a tooling defect

Lease `claude`, m1n1 `7de07c71` chainloaded over the rollback. Reviews: Mythos
PASS-with-must-fixes (`evidence/2026-10-25-review-5010-cpu-sysreg-diff.md`)
plus the run-2 plan. Reads only (`mrs` under the m1n1 exception guard).

## Run 1: wedged with no attribution

A blind sweep of every `s3_{0-7}_c15_c{0-15}_{0-7}` encoding. m1n1 started
all secondaries (CPU index 0 to 14). Then there was no output: stdout was
block-buffered through `tee`. The proxy was dead at the 20 min timeout, and
the machine was recovered by reboot. Which read hung is unknown. The script
was narrowed to the registers m1n1 names in `cpu_regs.h`.

## Run 2: cpu0 complete; secondaries cannot execute the proxy code buffer

First pass (Mythos list): 21 architectural ID/MMU registers plus 42 named
configuration registers on cpu0, cpu1 and cpu5. JSON was written after every
read, and the progress file before every read.

- **cpu0 (boot P, MPIDR 0x80010100, MIDR 0x611f0551): all 63 read**, 51
  defined and 12 UNDEF (`run2-sysregs.json`). Key values: `ACTLR_EL2=0xc00`,
  `HCR_EL2=0x32488000038`, `HID4=0x30800000000`, `HID5=0x0082cf605741ef11`,
  `HID6=0x006598432ca18818`, `HID7=0x1665a00008001000`,
  `HID11=0x4000000000201`, `HID18=0x40028006020`, `SPRR_CONFIG_EL1=0`,
  `APCTL_EL2=0xc`, `ACC_CFG=0xd`, `CYC_OVRD=0`.
- **cpu1 (E, MPIDR 0x1): its first three reads returned None, and the fourth
  rebooted m1n1.** The m1n1 console shows
  `ESR 0x86000000 (instruction abort (current))`, then
  `Unhandled exception, rebooting...`. The secondary took an instruction
  abort at the proxy code buffer, which `ProxyUtils.exec` calls through the
  `REGION_RX_EL1` alias: executable on cpu0, evidently not on the secondaries
  in this m1n1. The exception guard skipped the first three aborts; the
  fourth was unhandled. **This is a tooling defect. It says nothing about the
  CPU or about 205.**

Per the agreed rule (stop after two wedges in one lease), run 3 was not
attempted.

## Fix for run 3 (offline, next lease)

Call secondaries at the code buffer's physical address (region 0: pass
`call=(secondary_call(cpu), 0)` to `u.mrs`) rather than the RX_EL1 alias, or
verify m1n1's secondary MMU mapping first with a single NOP call. Keep the
async spin_table poll, the per-read progress, the JSON after every read, and
the stop-after-two-wedges rule. cpu0's baseline is already on disk; run 3
needs cpu1, cpu5 and cpu6.
