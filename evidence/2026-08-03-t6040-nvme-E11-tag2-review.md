# T6040 NVMe E11 — non-zero TCB slot refuted

Date: 2026-08-03

Ticket: 194

Rig use by this review: **none**. This is an offline review of the completed
E11 run and its retained host artifacts.

## Verdict

**PASS with a provenance caveat.** The retained candidate demonstrably uses
NVMe command tag 2 and NVMMU TCB slot 2, and its transcript records 200
successful single-LBA reads across roughly three depth-64 CQ wraps. A non-zero
TCB slot by itself therefore does not reproduce Linux's first-wrap firmware
assert and is refuted as the trigger.

This does not prove that IRQ-context completion is the cause. It only removes
the tag/TCB-slot hypothesis and leaves IRQ-context completion, live admin-queue
interaction, and any other still-unmatched Linux/m1n1 behavior as candidates.

## Exact code-path review

`nvme_exec_command()` uses the selected tag consistently:

```text
queue_cmd = &q->cmds[tag]
tcb       = &q->tcbs[tag]
queue_cmd->tag = tag
tcb->slot_id   = tag
```

Disassembly of the retained ELF at `nvme_exec_command+0x34` contains
`mov w23, #0x2`. The same register is then stored to the command tag byte at
`+0x82` and the TCB slot byte at `+0x102`. This proves that the tested binary
used tag 2 for both structures; the result does not rely on the filename.

The retained ELF exposes `nvme_init`, `nvme_read`, and `nvme_shutdown`, but no
`nvme_write` symbol. The host probe's wrap mode calls only init, 200 bounded
single-LBA reads, and shutdown. It rejects a wrap count outside 1..1024.

## Transcript review

The transcript passes the fail-closed identity gate for J614s/Mac16,8,
chip `0x6040`, board 4, and the exact ANS/SART nodes. RTKit/NVMe initializes at
`0x44dcc0000`. Progress is recorded every 16 reads through `192/200`; the
script prints its success result only after the loop exits with no failed read:

```text
RESULT: E1 PASS — 200 reads, ~3 CQ wraps survived by m1n1's scheme.
```

The generic probe still labels this mode `E1`; for this run the binary's tag-2
disassembly is what makes it E11.

Shutdown reports the already-known delete-SQ and delete-CQ status 2 warnings,
then the proxy returns zero bytes. Those events occur after all 200 reads and
do not invalidate the E11 discriminator, but they mean the transcript does not
prove a clean shutdown or healthy rig handoff.

## Reproduction audit

A fresh out-of-tree build from the same source state, with nightly Rust,
`M1N1_VERSION_TAG=t6040-e11-tag2`, and
`EXTRA_CFLAGS=-DT6040_E11_TAG=2`, compiled successfully. Its NVMe tag-2
instructions and section layout match, but its raw image did **not** reproduce
byte-for-byte. Rust-generated anonymous symbol/string ordering differs in the
out-of-tree build. Accordingly, preserve the exact live artifact above for
history and create a newly reviewed, hash-pinned candidate for any follow-up;
do not claim the E11 image is clean-build byte-reproducible.

## Ticket consequence

Ticket 194 can close as a negative discriminator. Ticket 195 is the stated
admin-traffic follow-up; its structured dependency is corrected to 194 so the
ticket graph matches its description. Any IRQ-context test needs a separate
Linux-side artifact and exact review—it is not established by E11 and cannot
be emulated merely by setting the m1n1 CQ interrupt flag.
